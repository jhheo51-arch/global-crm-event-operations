# Global CRM Event Operations

아이아이컴바인드의 `Global CRM Marketing Specialist` 공고를 읽고, 제가 이 업무를 맡는다면 VIP 행사 전후의 고객 정보를 어떻게 관리할지 정리한 프로젝트입니다.

실제 VIP 행사를 운영한 경험이 있다고 가정하지 않았습니다. 아이아이컴바인드 공식 채용 사이트와 젠틀몬스터, 탬버린즈, 누데이크, 어티슈, 누플랏의 공식 채널을 먼저 확인하고, 관련 기사와 공개 방문 후기를 따로 읽었습니다. 탬버린즈 카디퓨저 프라이빗 프리뷰를 가정해 고객 선정부터 행사 후 30일까지의 흐름을 만들었으며 고객 수와 전환율은 계산 방법을 설명하기 위한 값입니다.

실제 행사 운영 경험의 빈칸을 조사와 운영 설계로 얼마나 구체적으로 준비할 수 있는지 보여주기 위해 만들었습니다. 공개 자료에서 확인한 사실, 제가 세운 가정과 계산용 수치를 구분하고 고객 단계, 담당자, 다음 업무와 측정 기준을 정리했습니다.

![SCENT LOOP 프로젝트 화면](assets/project-overview.png)

## 1. 문제 정의

VIP 행사가 끝난 뒤 초청 이유, 현장 경험, 마케팅 동의와 상담/예약 요청이 서로 다른 문서에 흩어지면 담당자가 다음 행동을 놓칠 수 있습니다. 이 프로젝트는 **행사 전 선택 이유부터 행사 후 담당 업무까지 한 흐름으로 관리하는 구조**를 다룹니다.

## 2. 자료와 가정

채용공고, 브랜드 공식 채널, 공개 기사와 개별 방문 후기를 구분해 읽었습니다. SCENT LOOP라는 행사명과 고객 수 및 전환율은 계산 구조를 보여주기 위한 가상값입니다. 실제 고객 명단, 매출과 내부 CRM 자료는 사용하지 않았습니다.

## 3. 지표 분석

가상 고객 흐름을 `초청 240 → RSVP 156 → 방문 확정 132 → 참석 116 → 체험 104 → 마케팅 동의 82 → 후속 반응 47 → 관계 행동 28`로 나눴습니다. 각 단계의 분모를 고정해 수치가 좋아 보이도록 계산 기준이 바뀌지 않게 했고, 참석과 마케팅 수신 동의도 별도 지표로 분리했습니다.

## 4. 내가 한 판단

고객이 왜 초대됐고 무엇에 관심을 보였는지, 후속 행동은 누가 언제 맡는지를 기록해야 한다고 판단했습니다. 국가와 브랜드가 달라도 `Invite → Experience → Consent → Loyalty` 흐름을 공통 기준으로 사용하도록 설계했습니다.

## 5. 작동 화면

화면에서 고객군, 행사 단계, 장소와 운영 조건, 누락 업무, 후속 CRM 계획을 이동하며 확인할 수 있습니다. 외부 제출에서는 아래 PDF와 Excel을 사용하고, 화면 이미지는 구현 범위를 빠르게 이해하기 위한 미리보기입니다.

## 6. 검증 결과

고객 단계 합계, 전환율의 분자와 분모, 누락 업무, 출처 표시와 실행 파일을 자동 검사하도록 구성했습니다. PDF, Excel과 GitHub의 핵심 수치가 일치하는지 확인했지만 실제 행사 성과를 검증한 결과는 아닙니다.

## 7. 아직 확인하지 못한 것

- 실제 회사의 고객 등급, 국가별 동의 기준과 사용 중인 CRM 구조
- 실제 행사 현장에서 기록할 수 있는 정보의 양과 담당자 부담
- 초청 기준과 후속 행동이 재방문, 상담과 구매에 미치는 효과
- 실무자 검토 후 유지, 수정 또는 삭제해야 할 항목

## 왜 만들었나

팝업이 끝난 뒤 다음과 같은 정보가 사라지기 쉽다고 생각했습니다.

- 누구를 왜 초대했는가
- 예약한 고객이 실제로 왔는가
- 현장에서 어떤 제품과 향에 관심을 보였는가
- 연락에 동의했는가
- 상담이나 예약 요청을 누가 언제 처리해야 하는가
- 행사 후 구매와 재방문을 어떤 기준으로 셀 것인가

이 질문을 확인할 수 있도록 행사 전의 초청 이유와 행사 후 담당 업무가 이어지는 표를 먼저 만들었습니다.

## 대표 기획안: SCENT LOOP

SCENT LOOP는 제가 붙인 프로젝트 이름입니다. `SCENT`는 현장에서 고른 향, `LOOP`는 그 선택이 상담/예약/재방문으로 이어지는 과정을 뜻합니다. 아이아이컴바인드나 탬버린즈가 실제로 사용한 행사명은 아닙니다.

가상 초청 고객 240명을 다음 네 그룹으로 나눴습니다.

- 기존 우수, 재구매 고객 70명
- 카디퓨저와 자동차 생활에 관심을 보인 잠재 고객 80명
- 브랜드와 맞는 콘텐츠 크리에이터 30명
- 과거 구매 뒤 최근 반응이 없는 VIP 60명

초청, RSVP, 방문 확정, 참석, 체험, 마케팅 동의, 후속 반응, 상담/예약/구매를 각각 다른 단계로 셌습니다. 행사 참석과 마케팅 수신 동의도 분리했습니다.

## 공고의 업무를 프로젝트에 옮긴 방식

| 공고의 담당업무 | 제가 만든 내용 |
|---|---|
| 고객 세그먼트와 시장별 CRM 캠페인 | 네 고객군의 선정 이유, 제외 조건, 혜택, 다음 연락 조건 |
| VIP/VIC 프리뷰, 론칭, 팝업, 매장 이벤트 여정 | 행사 8주 전부터 행사 후 30일까지의 고객, 운영 일정 |
| 리테일, 콘텐츠, 디자인 협업 | 수용 인원, 재고, 공개 범위, 초청물 승인과 인계 항목 |
| 행사 결과 분석과 다음 개선 | 단계별 분자, 분모, 이탈 인원, 후속 업무, 다음 시험 질문 |

## 제가 확인하고 정한 것

1. 목표 직무 공고와 아이아이컴바인드의 공식 브랜드, 행사 자료, 공개 방문 후기를 역할별로 나눠 읽었습니다.
2. 대기, 품절, 체험 마감 사례를 현장 기록 항목과 후속 업무에 반영했습니다.
3. 전환율이 좋아 보이게 분모를 바꾸지 않도록 계산 기준을 먼저 정했습니다.
4. 직접 확인하지 못한 내용과 가상 수치는 문서마다 표시했습니다.
5. 서울시 공공데이터와 Open-Meteo를 연결해 장소와 행사 시간대의 운영 조건도 함께 볼 수 있게 했습니다.

기획 범위와 판단 기준을 먼저 정한 뒤 웹 화면과 문서를 구현했고, 문구, 계산식, 화면을 다시 확인했습니다.

인터넷에 공개된 아이아이컴바인드 관련 글을 모두 수집한 전수 조사는 아닙니다. 2026-10-07에 접근할 수 있었고 목표 직무와 대표 기획안에 직접 필요한 자료를 선별했습니다. 실제 고객 수, 매출, 초청 기준과 내부 CRM 시스템은 확인하지 못했습니다.

## 공개 후기를 사용한 기준

- 공식 자료는 행사 시기와 브랜드가 공개한 의도를 확인하는 데만 사용했습니다.
- 개인 후기는 한 사람이 특정 시점에 겪은 경험으로만 기록했습니다.
- 제가 직접 방문한 것처럼 표현하지 않았습니다.
- 후기 한 건을 전체 고객의 공통 불편으로 확대하지 않았습니다.
- 작성자의 이름과 계정 정보는 고객 데이터로 수집하지 않았습니다.

## 실행 방법

Node.js 22 이상에서 실행할 수 있습니다.

```bash
npm install
npm start
```

터미널에 표시된 주소를 브라우저에서 엽니다. 서울시 API 키는 `.env.example`을 참고해 로컬 `.env`에 넣습니다. `.env`는 GitHub에 올라가지 않습니다.

```bash
npm test
npm run build
node verify-worker.mjs
```

- `npm test`: 고객 단계, 계산식, 누락 업무, 출처 표시를 확인합니다.
- `npm run build`: 배포 파일을 만듭니다.
- `node verify-worker.mjs`: 화면 파일과 API 경로를 확인합니다.

## 이 프로젝트에서 하지 않은 것

- 실제 고객 명단이나 브랜드 내부 데이터를 사용하지 않았습니다.
- 실제 초청장 발송, 회원 가입, 결제는 진행하지 않았습니다.
- 가상 전환율을 실제 행사 성과로 제시하지 않습니다.
- 실제 적용 전에는 회사의 고객 정의, 국가별 개인정보, 광고 규정, 현장 담당자의 확인이 필요합니다.
