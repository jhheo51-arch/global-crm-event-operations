# Global CRM Event Operations / PRD

## 1. 제품 요약

VIP/VIC 프리뷰, 론칭, 팝업과 매장 이벤트에서 고객이 단계 사이에 누락되지 않도록 초청 이유, 방문 상태, 현장 경험, 마케팅 동의, 후속 요청과 담당 업무를 하나의 흐름으로 관리하는 운영 모델입니다.

대표 사례인 `SCENT LOOP`는 탬버린즈 카디퓨저 프라이빗 프리뷰를 가정합니다. 실제 행사명이나 실제 운영 성과가 아니며, 모든 고객 수와 전환율은 계산 구조를 검토하기 위한 가상값입니다.

`SCENT`는 현장에서 확인한 고객의 향 선택과 사용 장면을, `LOOP`는 동의한 고객의 선택을 상담/예약/재방문으로 이어가는 CRM 운영을 뜻합니다.

## 2. 해결할 문제

행사 방문객 수만 집계하면 다음 정보가 사라지기 쉽습니다.

- 누구를 왜 초대했는가
- 예약한 고객이 실제로 방문했는가
- 어떤 제품/향/체험에 관심을 보였는가
- 체험이 중단되거나 혜택이 소진됐을 때 어떤 선택지를 제공했는가
- 행사 참석과 별도로 마케팅 수신에 동의했는가
- 상담, 예약, 재입고 요청을 누가 언제 처리해야 하는가
- 행사 후 행동을 어떤 분모와 기준으로 비교할 것인가

이 제품은 단계별 고객 상태와 다음 업무를 함께 남겨 오프라인 경험이 후속 CRM으로 이어지게 합니다.

## 3. 목표 사용자와 협업자

### 주 사용자

- HQ Global CRM 담당자
- 시장별 Local CRM 담당자
- Guest Manager와 Client Care 담당자

### 협업자

- 리테일/현장 운영: 수용 인원, 직원 배치, 대기, 재고, 서비스 복구
- 콘텐츠: 공개 범위, 엠바고, 메시지, 시장별 표현
- 디자인/공간: 초청장, 현장 사인, 체험물, 동의 화면
- 이커머스: 상품 정보, 재고, 구매, 예약 연결
- 법무, 개인정보: 국가별 동의 문구, 보관 기간, 접근 권한

## 4. 목표와 제외 범위

### 목표

1. 고객을 초대한 이유와 제외 조건을 설명할 수 있어야 합니다.
2. 초청부터 행사 후 30일까지 고객 상태를 같은 식별자로 연결해야 합니다.
3. 참석, 체험, 마케팅 동의, 후속 반응을 서로 다른 행동으로 기록해야 합니다.
4. 단계 사이에서 빠진 고객을 삭제하지 않고 담당 업무로 남겨야 합니다.
5. 지표의 분자, 분모를 고정하고 시장별로 같은 정의를 사용할 수 있어야 합니다.
6. 본사 공통 기준과 현지 시장 조정 항목을 분리해야 합니다.

### 제외 범위

- 실제 아이아이컴바인드 고객, 매출, 행사 성과의 재현
- 실제 VIP/VIC 등급 기준의 추정
- 개인정보 처리방침과 국가별 법률의 최종 확정
- 실제 메시지 발송, 결제, 회원 가입과 재고 차감
- 공개 후기 한 건을 전체 고객 경험으로 일반화하는 분석

## 5. 근거와 가정의 경계

| 자료 | 사용하는 범위 | 사용하지 않는 범위 |
|---|---|---|
| 채용공고 | 직무의 담당업무, 협업 범위, 필요 역량 | 내부 KPI, 조직도 추정 |
| 브랜드 공식 자료 | 행사, 제품, 공간, 공개 일정 확인 | 실제 고객 반응, 성과 추정 |
| 공개 방문 후기 | 특정 시점의 대기, 품절, 체험 장면 확인 | 전체 고객의 공통 문제로 일반화 |
| 서울시, 날씨 데이터 | 장소와 행사 시간대의 운영 조건 확인 | 특정 장소의 장기 성과 판단 |
| 가상 고객 수 | 퍼널, 분모, 누락 인원 계산 검산 | 실제 성과 또는 목표 달성 주장 |

## 6. 핵심 고객 여정

`선정 → 초청 → RSVP → 방문 확정 → 체크인 → 체험 → 마케팅 동의 → 후속 반응 → 관계 행동`

| 단계 | 담당자가 답해야 할 질문 | 남길 데이터 | 다음 행동 |
|---|---|---|---|
| 선정 | 왜 이 고객을 초대하는가 | 시장, 고객군, 선정 이유, 발송 제외 | 적격 고객만 개인화 초청 |
| RSVP | 언제 방문하고 어떤 지원이 필요한가 | 응답, 시간, 동반인, 언어, 접근 요청 | 확정, 대기, 거절 분기 |
| 체크인 | 실제 도착했고 얼마나 기다렸는가 | 도착, 대기 시작, 체험 시작, 노쇼 사유 | 혼잡 대응, 담당자 호출 |
| 체험 | 무엇을 선호했고 어디에서 끊겼는가 | 제품, 향 선호, 완료/중단 사유, 상담 요청 | 개인화 안내, 샘플, 재예약 |
| 동의 | 어떤 목적과 채널의 연락을 원하는가 | 목적, 채널, 동의 시각, 정책 버전 | 동의 고객만 후속 등록 |
| 후속 | 다음 결정에 어떤 정보가 필요한가 | 발송, 클릭, 회신, 상담, 인계 상태 | 사용 팁, 상담, 예약, 재입고 |
| 관계 | 30일 안에 어떤 행동이 있었는가 | 구매, 예약, 상담, 재방문, 수신 거절 | 유지 프로그램 또는 빈도 축소 |

## 7. 고객군 가정

| 고객군 | 가상 초청 | 선정 기준 | 제공 가치 | 행사 뒤 행동 |
|---|---:|---|---|---|
| 기존 우수, 재구매 고객 | 70 | 향 제품 구매와 재구매 관계 | 선호 기반 프리뷰, 리필 케어 | 사용 팁, 리필 시점 안내 |
| 고관여 잠재 고객 | 80 | 카디퓨저, 자동차 생활 관심 신호 | 향 비교, 차량 환경 상담 | 상담, 예약, 미구매 사유별 후속 |
| 콘텐츠 크리에이터 | 30 | 브랜드 적합성, 콘텐츠 품질, 공개 범위 | 공개 전 세계관, 정확한 제품 자료 | 엠바고, 표기, 반응 확인 |
| 휴면 VIP | 60 | 과거 구매 후 최근 관계 신호 없음 | 부담 없는 재활성화 체험 | 무반응 시 반복 발송 중지 |

고객군은 초청 이유가 서로 다른 네 경로를 시험하기 위한 가정입니다. 실제 적용 전에는 회사의 VIP/VIC 정의, 시장별 고객 규모, 제외 기준과 접촉 정책을 먼저 확인해야 합니다.

## 8. 기능 요구사항

### FR-01 / 고객 선정

- 고객 ID의 중복을 확인합니다.
- 시장, 고객군, 선정 이유와 발송 제외 상태가 모두 있어야 초청할 수 있습니다.
- 제외된 고객에게는 메시지를 발송하지 않습니다.

### FR-02 / RSVP와 정원

- 응답, 거절, 미응답을 구분합니다.
- 시간대, 동반인, 언어와 접근성 요청을 기록합니다.
- 정원 초과 고객은 대기 또는 대체 시간을 선택할 수 있어야 합니다.

### FR-03 / 현장 체크인

- 방문 확정만으로 참석 처리하지 않고 체크인 시각을 요구합니다.
- 대기 시작과 체험 시작 시각을 구분합니다.
- 노쇼는 실패로 단정하지 않고 운영 연락 범위에서 선택형 사유를 남깁니다.

### FR-04 / 체험과 서비스 복구

- 체험 완료와 중단을 구분합니다.
- 체험 마감, 대기, 재고, 혜택 소진과 시간 부족을 중단 사유로 남길 수 있어야 합니다.
- 고객이 대체 샘플, 재예약, 재입고 안내 또는 종료 중 하나를 선택할 수 있어야 합니다.

### FR-05 / 동의와 개인정보

- 행사 참석, 촬영 동의, 마케팅 수신 동의를 별도로 다룹니다.
- 마케팅 동의에는 목적, 채널, 동의 시각과 정책 버전이 필요합니다.
- 거절/미확인 고객은 마케팅 후속에서 제외합니다.

### FR-06 / 후속 CRM

- 메일 열람은 후속 반응으로 계산하지 않습니다.
- 클릭, 회신, 상담 요청, 예약과 재입고 요청처럼 고객 의도가 확인되는 행동을 기록합니다.
- 반응이 없는 고객은 정해진 접촉 횟수 이후 휴면 처리합니다.

### FR-07 / 누락 업무

- 단계 사이 이탈 인원마다 원인, 고객 선택권, 담당자, 처리 기한과 완료 근거를 둡니다.
- 담당자 또는 근거가 없으면 완료로 처리할 수 없습니다.
- 고객이 기다리는 상담, 예약, 재고 요청을 우선 표시합니다.

### FR-08 / 성과 계산

- KPI마다 분자, 분모, 기간, 중복 제거 기준을 고정합니다.
- 미측정, 0명과 0분모를 구분합니다.
- 시장별 결과를 비교할 때 같은 이벤트 이름과 산식을 사용합니다.

### FR-09 / 글로벌 운영

- HQ는 브랜드 핵심 문장, 고객군 코드, 이벤트 이름, KPI와 최소 동의 원칙을 관리합니다.
- Local 팀은 언어, 채널, 발송 시각, 규정 문구, 예약 방식, 혜택 재고와 현장 응대를 조정합니다.
- 공통 기준과 현지 변경 사항의 승인 이력을 남깁니다.

### FR-10 / 근거와 결과물

- 공식 자료, 기사, 공개 후기와 가상값을 구분해 표시합니다.
- PDF의 판단, Excel의 계산과 업무표, GitHub의 근거가 같은 용어와 수치를 사용해야 합니다.

## 9. 가상 퍼널과 KPI

| 단계 | 가상 인원 | 고정 분모 | 비율 |
|---|---:|---|---:|
| 초청 | 240 | 선정 고객 | - |
| RSVP 응답 | 156 | 초청 240 | 65.0% |
| 방문 확정 | 132 | 응답 156 | 84.6% |
| 실제 참석 | 116 | 확정 132 | 87.9% |
| 체험 완료 | 104 | 참석 116 | 89.7% |
| 마케팅 동의 | 82 | 참석 116 | 70.7% |
| 후속 반응 | 47 | 동의 82 | 57.3% |
| 관계 행동 | 28 | 동의 82 | 34.1% |

이 수치는 성과 예측이 아닙니다. 순차 감소, 분모 고정, 단계별 누락 인원과 담당 업무가 함께 맞는지 검산하기 위해 정했습니다.

## 10. 브랜드별 적용 차이

| 브랜드 | 핵심 체험 신호 | 반드시 남길 데이터 | 후속 행동 |
|---|---|---|---|
| 젠틀몬스터 | 시착, 피팅, 스타일 상담 | 시착 제품, 피팅 반응, 구매/보류 이유 | 상담, 재고, 수선, 재방문 |
| 탬버린즈 | 향 비교, 사용 장면, DIY | 향 선호, 체험 완료, 샘플/재예약 선택 | 사용 팁, 상담, 리필, 재예약 |
| 누데이크 | 메뉴, 차 비교, 품절, 대기 | 선호 메뉴, 알레르기/식이 요청, 품절 대안 | 예약, 대체 메뉴, 재입고성 안내 |
| 어티슈 | 피팅, 사이즈, 형태, 재고 | 시착 제품, 사이즈, 착용 반응, 재고 요청 | 재고 알림, 스타일링, 재방문 |
| 누플랏 | 제품 관람, 실사용, 선물 목적 | 관심 제품, 사용 장면, 세트/선물 상담 | 관리법, 선물 상담, 교차 체험 |

공통 고객 ID를 사용할 수 있어도 브랜드별 관심, 동의와 성과는 합치지 않습니다.

## 11. 위험과 대응

| 위험 | 대응 | 확인 지표 |
|---|---|---|
| 예약 혜택, 체험 소진 | 대체 샘플과 재예약 중 고객 선택 | 대체안 수락, 7일 반응 |
| 대기 목표 초과 | 도착 분산, 예상 대기 고지, 담당자 호출 | 평균/최대 대기, 조기 퇴장 |
| VIP 정보 노출 | 현장 식별명, 최소 권한, 촬영 동의 분리 | 접근 기록, 동의 누락 |
| 동의하지 않은 고객 발송 | 체험 혜택 유지, 마케팅 발송 제외 | 잘못된 발송 0건 |
| 국가별 메시지 불일치 | HQ 핵심 문장과 Local 승인 분리 | 승인 이력, 수정 건수 |
| 담당자 누락 | 책임자, 기한, 근거 없는 완료 차단 | 미처리, 지연 업무 수 |

## 12. 완료 기준

- 네 고객군의 초청 합계가 240명과 일치합니다.
- 퍼널은 앞 단계보다 뒤 단계 인원이 커지지 않습니다.
- 각 KPI의 수식이 PDF와 Excel에서 같습니다.
- 참석과 마케팅 동의가 별도 상태로 기록됩니다.
- 단계 사이 이탈 인원이 모두 누락 업무표에 남습니다.
- 업무 완료에는 담당자와 완료 근거가 필요합니다.
- 공식 자료, 공개 후기와 가상 데이터의 표시가 분리됩니다.
- PDF와 Excel 다운로드 파일명이 README와 웹 화면에서 일치합니다.
- 실제 고객 데이터와 API 키가 GitHub에 포함되지 않습니다.
